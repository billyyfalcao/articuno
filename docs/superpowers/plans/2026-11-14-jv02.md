## Decisões

- POST /api/v1/internal/vision-events recebe JSON do VisionEvent; GET da mesma
  rota com /{event_id} permite consultar o registro autenticado. Sem sessões.
- X-Internal-API-Key obrigatório; INTERNAL_API_KEY ausente desabilita rotas
  internas com 503, mas preserva health. Chave configurada deve ter 32..256
  caracteres ASCII sem espaços. Comparação constante; nunca logar chave/body.
- JSON estrito: tipos sem coerção, campos extras/duplicados rejeitados, fuso
  explícito, UUID, padrões brasileiros, regras de nulidade/confiança/transição
  do modelo Python. Limite 16 KiB. Sem lista fixa de câmeras: a configuração de
  câmera/setor e os efeitos de negócio serão tratados no JV-03.
- Canonicalizar campos opcionais ausentes como null, UUID, instante UTC e
  confiança decimal para comparação independente da formatação JSON.
- SQLite: migração transacional 1→2; tabela vision_events com event_id PK,
  payload canônico e resposta persistida. INSERT ... ON CONFLICT DO NOTHING;
  resposta original idêntica para replay, 409 para mesmo ID com outro conteúdo.
- HTTP 200 após registro durável; status RECORDED não significa sessão criada.
  400 JSON inválido, 401 chave ausente/incorreta, 413 tamanho, 415 mídia,
  422 campos inválidos, 503 banco/receptor indisponível. Sem duplicar cliente Python.
